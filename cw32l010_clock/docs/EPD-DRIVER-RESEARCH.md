# 出厂驱动分析与窗口刷新优化

检索、备份反汇编核对与实现日期：2026-10-04。
窗口驱动已实现并通过主机测试。2026-10-04 未连接调试器；
2026-10-19 已烧录并完成全片回读，但用户反馈按键后画面异常，未通过实机显示验收。
本次新增的 2.66 寸 LUT 检索见文末，UC8251 系列是新的格式匹配线索，尚未确认本机料号。

## 结论

2026-10-04 首轮找到的协议对照是 GDEW026T0 / GDEW026M01 的 GxEPD2 驱动：
分辨率同为 152x296，使用 `0x10` / `0x13` 两路图像数据、`0x12` 刷新，
BUSY 低有效，并具有差分更新流程。
这是协议相似性判断，不是本机控制器型号确认。

本机原固件每个 LUT 命令发送 56 字节，而上述驱动使用 44 / 42 字节。
初始化、电压、PLL 和波形内容也不同。发送长度差异本身不能证明控制器不同，
但现有证据不足以安全照搬波形或电压设置。
窗口参数与指令顺序使用本机出厂固件的已验证实现，而非网络示例。

## 本机已确认事实

依据：[原固件逆向记录](/Users/henry/Documents/ChatGPT/小钟/cw32l010_epd_analysis.md:20)。

- 物理分辨率 152x296；界面横屏 296x152；确切 FPC / 控制器料号未知。
- `0x10` 为旧图像，`0x13` 为新图像；整屏时各 5624 字节，局刷仅发送窗口数据。
- `0x12` 刷新；`0x04` 开电源；`0x02` 关电源；`0x07 : A5` 深睡眠。
- `0x20..0x24` 每表 56 字节，来自原机备份，不是网络快刷表。
- 原固件包含 `0x90/0x91/0x92` 路径；本次自定义驱动已使用。
- MCU RAM 只有 4 KiB，不能直接装下一个完整的 5624 字节帧缓冲。

## 出厂固件的实际刷新流程

证据为 `cw32l010_original_64k.bin` 的 Thumb 反汇编，不是按相似芯片猜测。
原始 64 KiB 备份 SHA-256：
`0f92f36672594320223d3a23815bd04f864b1163875ef61d41a2460bd0c80c71`。

| 地址 | 已确认行为 |
| --- | --- |
| `0x2cb8`、`0x2d44..0x2ed8` | 比较前后场景描述、检查反色兼容性、合并变化区域；七次局刷后全刷 |
| `0x30e6` | 按行生成图像，只发送窗口的 x 字节跨度和 y 行范围，不保留整帧 |
| `0x3234` | 初始化分辨率、PLL、电压、五张 56 字节 LUT，`0x04` 开电源并等 BUSY |
| `0x33a0` | 校验包含末端的窗口坐标，x0 是 8 的倍数，x1 低三位为 7，最大 151x295 |
| `0x381a` | `0x12` 刷新并等待 BUSY |
| `0x3800` | `0x02` 关电源、等 BUSY，再 `0x07 : A5` 深睡眠 |
| `0x3838` | BUSY 低有效、1 ms 起始等待、10 s 超时，释放后再等待 10 ms |

局刷指令顺序：

```text
复位 -> 初始化 / 原机快刷 LUT -> 04 -> 等 BUSY
90 [x0 x1 y0_hi y0_lo y1_hi y1_lo 01]
91 -> 10 [窗口旧图像] -> 13 [窗口新图像]
12 -> 等 BUSY -> 92 -> 02 -> 等 BUSY -> 07 A5
```

两点纠正：出厂固件也是每轮初始化并深睡眠，不是一直保留电源；
本机窗口参数在 `0x91` 之前发送，与下方 GxEPD2 的 `0x91 -> 0x90` 顺序不同。
本次保留本机顺序和末字节 `01`，不直接移植相似屏的窗口标志。

## 已核对的相似驱动

### 1. GDEW026T0 / GxEPD2_260

原始源码：
[驱动实现](https://github.com/ZinggJM/GxEPD2/blob/master/src/epd/GxEPD2_260.cpp)、
[参数定义](https://github.com/ZinggJM/GxEPD2/blob/master/src/epd/GxEPD2_260.h)。

- 源码标注控制器 IL0373，项目支持清单写为 UC8151 (IL0373)。
- 152x296，BUSY 低有效；写旧图像 `0x10`，写新图像 `0x13`。
- `_Init_Part()` 上传差分 LUT；进入同一更新模式后不必每次重新初始化。
- `_PowerOn()` 仅在电源未开启时执行；`hibernate()` 是独立操作。
- `0x91 -> 0x90 -> 写窗口图像 -> 0x92` 用于局部 RAM 写入，横坐标按 8 像素对齐。
- 重要：`usePartialUpdateWindow=false`，注释说明是为获得更好的图像。
  因此局部传数据不等于一定局部驱动屏幕，更不能承诺刷新时间按面积同比减少。
- 头文件参考值：全刷 1600 ms、局刷 1300 ms，代码附示例 BUSY 测量值。
  这些不是本机实测，也不是所有温度、波形下的固定耗时。
- LUT 上传长度为 VCOM 44 字节、其余四表 42 字节，不与本机直接匹配。

### 2. GDEW026M01 / GxEPD2_260_M01

原始源码：
[驱动实现](https://github.com/ZinggJM/GxEPD2/blob/master/src/epd/GxEPD2_260_M01.cpp)、
[参数定义](https://github.com/ZinggJM/GxEPD2/blob/master/src/epd/GxEPD2_260_M01.h)。

- 同为 152x296、BUSY 低有效、`0x10/0x13/0x12` 协议。
- 全刷使用 OTP 设置；差分更新另外配置寄存器与 44 / 42 字节 LUT。
- 保留电源和更新模式，局部刷新路径使用 `0x91/0x90/0x92`。
- 头文件参考值：全刷 3400 ms、局刷 1000 ms，不是本机实测。
- 源码明确称局刷波形为实验性；项目说明快刷仅适用于正常温度范围。
  不能因为分辨率一致就换用 DES 面板的波形。

### 3. Waveshare 2.9inch (D) / EPD_2in9d

厂家原始源码：
[EPD_2in9d.c](https://github.com/waveshareteam/e-Paper/blob/master/RaspberryPi_JetsonNano/c/lib/e-Paper/EPD_2in9d.c)。

- 分辨率 128x296，与本机不相同，但更新协议可供交叉核对。
- `EPD_2IN9D_DisplayPart()` 写局刷寄存器，进入 `0x91`，设置 `0x90`，写 `0x13`，再触发 `0x12`。
- 原示例设置的是整屏窗口；函数名含 Part 不代表传输区域一定很小。
- BUSY 等待、`0x12` 之后必要延迟、睡眠操作均有独立实现。
- 同样使用 44 / 42 字节 LUT；不直接移植分辨率、窗口数据或波形。

### 排除：DEPG0266BN / 常见 2.66 寸 SSD1680

原始源码：
[GxEPD2_266_BN.cpp](https://github.com/ZinggJM/GxEPD2/blob/master/src/epd/GxEPD2_266_BN.cpp)、
[支持清单](https://github.com/ZinggJM/GxEPD2/blob/master/README.md)。

## 改动前的额外开销

依据：[epd.c](/Users/henry/Documents/ChatGPT/小钟/cw32l010_clock/user/src/epd.c:60)、
[SPI 配置](/Users/henry/Documents/ChatGPT/小钟/cw32l010_clock/user/src/board.c:120)、
[更新调度](/Users/henry/Documents/ChatGPT/小钟/cw32l010_clock/user/src/main.c:65)。

1. `epd_start()` 不论全刷或快刷，都开始约 30 ms 的硬件复位流程。
2. 每次重传所有初始化寄存器、五张 LUT，再开电源并等待 BUSY。
3. 即使只移动菜单选中项，也重新生成并发送新旧两幅完整图像，共 11248 字节。
4. `0x12` 之后等待屏幕物理刷新完成，再关电源、等待、深睡眠。
5. 新帧开始写入后不再接受重定向；之后的按键变化要等当前更新结束。

相对出厂实现，已经确认的可避免开销是整屏生成与上传。
复位、初始化、关电源和深睡眠是原机也使用的策略，本次没有为了追求速度取消。

源码声明核心时钟 4 MHz，SPI 配置八分频。
若实机 SPI 源时钟为 4 MHz，则 SCK 为 500 kHz，
仅 11248 字节的线速传输下限约 180 ms，尚不含绘制和调度开销。
此值是条件计算，不是逻辑分析仪实测。`SPI_Speed_Low` 只是采样延后选项，
实际传输速度不能根据这个名称判断。

## 本次实现

- 比较单份绘制操作缓存中的旧、新操作，包含已移除元素，得到字节对齐的物理变化窗口。
  没有新增整帧缓冲；仅使用原有操作缓存、19 字节行缓存和栈上的色阶列。
- 快刷按出厂顺序发送窗口和旧、新图像。首次显示、反色变化和定期全刷仍使用整屏。
- 行渲染只计算窗口跨度；不再强制每行 SPI 传输后等待一个 SysTick。
  SPI 每次轮询最多处理 8 字节，行渲染之间仍返回主循环处理按键。
- 连续按键可在新图像开始前合并；正在传输的缓存保持不变。
  完成当前传输后先退出已进入的局刷模式，再设置新窗口、重写旧图像。
  新图像一旦开始传输就冻结，避免一轮波形使用混合场景。
- 全刷期间旧图像和窗口不随新场景变化，重定向只更新待显示场景，不重启旧图像上传。
  独立审查发现此前 150 ms 连按会在慢速 SPI 模型中持续重启旧图像；
  回归先复现失败，再验证首次显示和强制全刷都能前进到新图像，且旧图像只上传一次。
- 没有变化的绘制操作跳过旧、新图像上传和 `0x12` 波形。
  这类场景只更新已显示场景的元数据，不消耗七次局刷配额。
- 保留出厂电压、PLL、完整 LUT、BUSY 释放后的等待与每轮深睡眠。
  未提高 SPI 时钟，也未缩短物理波形。

主机回归中的双方图像传输量：

| 操作 | 改动前 | 窗口上传 |
| --- | --- | --- |
| 菜单选中项 0 -> 1 | 11248 字节 | 3264 字节，减少约 71% |
| 翻页主页分钟 34 -> 35 | 11248 字节 | 532 字节 |
| 时间编辑器分钟 34 -> 35 | 11248 字节 | 240 字节 |
| 菜单只更新后台分钟元数据 | 11248 字节 | 0 字节，不执行刷新波形 |

这是双方图像数据总量，不包含初始化和指令；不代表可见延迟减少 71%。
若 SCK 确为 500 kHz，仅图像数据的线速下限约从 180 ms 降到 52 ms。
真实 CPU 绘制耗时和屏幕 BUSY 必须另外测量。

`epd_metrics` 记录 `setup_ms / old_ms / new_ms / busy_ms / finish_ms / total_ms`，
以及 `image_bytes / rendered_rows / max_render_ms / refreshed`。
这些字段地址已写入构建 manifest 的 `debug_symbols`，可使用 SWD 读取。
`busy_ms` 是 `0x12` 之后的 BUSY 等待及必要释放延迟，不含开电源等待；
`setup_ms` 包含复位、初始化、开电源等待与窗口设置。
重定向时 `image_bytes` 包含被放弃的旧图像前缀，`old_ms` 包含重算窗口与重写旧图像。
成功完成时各阶段耗时之和等于 `total_ms`，有回归校验；字段在下一轮开始时重置。

## 2026-10-19 UC8251 单字节 PSR 对照试验

用户要求按 UC8251 驱动试验。控制器型号仍未由排线标识或读 ID 确认；
这次属于可回退的兼容性测试，不将手册差异直接认定为画面异常的根因。

## CW32L010 DMA 路径核对（2026-10-19）

为判断是否能把 UC8251 的整帧 SPI 发送交给硬件 DMA，核对了官方 CW32L010 用户手册 V1.2、CMSIS 头文件和本地固件库。

- 官方 SPI 章节的功能框图只有 APB、发送/接收缓冲、移位寄存器、波特率发生器和控制逻辑；SPI 特性列出 8 个中断源，并提供 TXE/RXNE 中断及查询方式，没有 DMA 控制器、DMA 通道映射或 DMA 请求描述。
- 本地芯片头文件没有 DMA 外设基址、DMA 控制器/通道结构、DMA 时钟门控、DMA IRQ 或 DMA 源文件；IRQ 表只有一个 SPI 全局中断。
- 固件库虽然声明了 `SPI_DMAReq_Tx`、`SPI_DMAReq_Rx` 和 `SPI_DMACmd()`，但两个请求值分别是 `0x00020000`、`0x00010000`。它们正好落在 `SPI_CR1.MODE[17:16]`，而该位域在 CW32L010 手册中定义为 `00` 全双工、`01` 单工发送、`10` 单工接收、`11` 单线半双工。
- `SPI_DMACmd()` 的实现直接对 `SPIx->CR1` 做按位置位/清位，因此不能把它当作真实 DMA 使能函数。调用发送请求可能把当前 SPI 模式改成单工发送，调用接收请求可能改成单工接收，两个同时置位则可能变成单线半双工。

结论：当前 CW32L010 没有可确认且可安全使用的 SPI DMA 路径。显示刷新应采用 SPI TXE 中断驱动发送，或继续使用当前的有界轮询/短突发方式；DMA 不能解决 UC8251 的 BUSY 波形等待，预计主要收益只在减少 CPU 等待和主循环阻塞。
只读监测记录一次后续完整双帧更新：总计 5494 ms，OLD 2610、NEW 2302、BUSY 331 ms，
最大单行绘制 53 ms。采样记录 `../evidence/refresh_20261019_223118.json`；
该监测在 60 秒心跳之后因 SWD 无回应中断，已取得的样本保留，不把它描述成完整 75 秒监测。
