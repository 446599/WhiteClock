# WhiteClock 烧录教程

本教程用于将 WhiteClock 固件写入兼容设备。烧录会替换应用程序，错误接线或错误镜像可能导致设备无法启动。操作前必须保留**本台设备**的原始完整备份。

## 1. 准备资料

准备电脑、可被 pyOCD 识别的 SWD 烧录器、数据线及稳定的连接夹具。参考硬件使用 WCH-Link；不同型号或工作模式不保证兼容，必须先检查能否被识别。

需要 AI 协助时，将 [AI 烧录交接文本](AI-FLASHING-HANDOFF.md)提供给具有本机文件和终端操作能力的 AI，同时补充：

- 电脑系统和仓库所在位置。
- 烧录器型号、接口标识及连接线照片。
- 电路板正反面、主控丝印和调试焊盘近照。
- 当前供电方式、屏幕是否正常，以及是否已有本机原始备份。

AI 只能提供建议、不能操作电脑时，应由操作者逐项执行并提供实际结果。不得将“命令已给出”当作“烧录已成功”。

## 2. 确认设备兼容性

| 项目 | 目标配置 |
|---|---|
| 主控 | CW32L010F8U6，Cortex-M0+，20 引脚 |
| Flash / RAM | 65,536 / 4,096 字节 |
| 屏幕 | 2.66 英寸黑白墨水屏，物理 152 × 296 |
| 界面方向 | 横向 296 × 152 |
| 调试接口 | SWD，不是串口 UART |
| 按键 | BACK PB2 / SET PB3，低有效 |

相同外观或屏幕尺寸不足以判断兼容。主控、板卡或屏幕批次不同，应先分析，不能直接写入。屏幕按 UC8251 协议路径驱动，但具体 FPC / 控制器料号没有完整确认；不要据此套用其他屏幕 LUT。

## 3. 接线

接线前断开电源。先根据板卡丝印、原理图或通断测量确认焊盘，不要根据照片方向猜顺序。

| 烧录器信号 | 设备信号 | MCU 引脚 |
|---|---|---|
| SWDIO / DIO | 调试数据 | PA7 |
| SWCLK / CLK | 调试时钟 | PA8 |
| GND | 地 | GND |
| VTref / 电平参考（若有） | 目标 MCU 的 VDD | 按烧录器说明连接 |

表中的 PA7 / PA8 是 MCU 信号名称，不是接插件的第 7 / 8 脚。仓库没有可通用于全部批次的焊盘排列图。

**供电规则：**

- 默认由设备自身供电，烧录器与设备共地；先测量目标 VDD，并核对烧录器的 SWD 电平与目标电压兼容。
- VTref 通常是参考输入，不等同于供电输出；标为 3V3 / VCC 的引脚也不能未经确认就连接。
- 只有确认板卡供电要求和烧录器输出规格后，才考虑由烧录器供电。不得让两路电源直接并联，不要将 USB 5 V 接到 SWD 或未知焊盘。
- 保持连接短而稳固。不要拉动屏幕排线；屏幕 RST（PA2）不是 MCU 的复位脚，不接作 nRESET。

## 4. 获取软件与正式固件

从 [WhiteClock Releases](https://github.com/446599/WhiteClock/releases)选择版本。保留同一版本的 BIN、HEX、`manifest.json`、许可与说明，不要混用不同版本的文件。

完整仓库包含烧录工具、芯片支持包和正式产物。设备写入工具只需要匹配的 BIN 和清单，不必为烧录现成固件安装 ARM 编译器。

以下为 macOS / Linux 示例，在 `cw32l010_clock/` 中执行；Windows 的环境激活及引号方式应由 AI 按实际终端调整：

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pyocd list
```

记录列表中**本机烧录器**的 ID，后续通过 `--probe` 指定。脚本中的默认 ID 仅对应参考开发环境，不应照搬。

## 5. 只读检查与备份

下面命令以 V1.0 目录为例，替换 `<烧录器ID>`。不要添加 `--flash` 或 `--restore`：

```sh
python -c 'from pathlib import Path; import sys; sys.path.insert(0,"tools"); import device; device.BUILD=Path("releases/whiteclock-v1-fast-20261020").resolve(); device.main()' \
  --probe <烧录器ID> --frequency 5000
```

工具读取芯片签名、容量、保护状态和全部 65,536 字节，生成仓库根目录下的 `evidence/before_时间戳.bin` 与 `device_时间戳.json`。只读检查会短暂暂停 CPU，但不擦写 Flash。

继续前必须确认：型号和容量匹配、保护级别为 0、完整备份大小为 65,536 字节、报告中的 `before_sha256` 与备份一致。应另存一份本机备份及其哈希。

仓库的 `cw32l010_original_64k.bin` 是参考设备的协议分析备份，脚本会校验它以保护流程完整性；**它不能替代你的设备备份，也不能作为另一台设备的通用恢复镜像**。

## 6. 烧录与完整校验

由 AI 汇报只读结果、目标版本及备份路径，确认无误后执行同一命令并追加：

```sh
--flash --expected-before-sha256 <刚刚读取的本机完整64KiB哈希>
```

`--expected-before-sha256` 不是 BIN 哈希，也不是 README 中的历史整片哈希。写入前会再次读取整片核对；若设置变化导致哈希不同，应重新检查，不能绕过保护。

工具按 512 字节页写入应用，保留最后一个应用页的未写字节和后续区域；应用上限 `0xFA00`，设置页 `0xFA00` / `0xFC00` 和安全页 `0xFE00` 不擦写。写入后逐字节比较全部 64 KiB，出现 `VERIFY PASS` 且报告 `verified: true` 后才允许正常启动。

保持供电和接线稳定直到校验完成。屏幕显示过画面、写入进度到 100% 都不等于完整校验通过。

## 7. 检查功能

确认主页方向和字形正常；SET 进入菜单，BACK 移动圆点，长按 BACK 返回。检查七套主题、主题保存、时间设置及主页 BACK 的番茄钟入口。番茄钟可选 5 分钟验证完成后的五次全刷提醒。

断电后应能保留显示设置。时间保持取决于设备供电及 RTC 状态；请单独核对日期和走时。芯片温度不能当作校准室温。

## 连接失败或写入中断

| 情况 | 处理 |
|---|---|
| 烧录器未列出 | 检查数据线、USB 接口、驱动及烧录器模式，不执行写入 |
| 芯片无回应 / 读取超时 | 停止操作，检查供电、共地、接触和 DIO / CLK；可在稳定连接后尝试 1 kHz |
| 型号、容量或保护状态不符 | 停止，不解锁、不整片擦除 |
| 写入前哈希不符 | 重新只读备份并核对变化原因，不改成任意哈希强行继续 |
| 已开始写入但未校验通过 | 保留当前报告、写入前备份和 `program_pages_*.bin`；不得宣称原固件完好或反复复位启动 |

写入中断后，先恢复可靠连接，再由 AI 将完整读回与“本次目标页负载 + 本次备份的保留尾部”比较。相同则无需重复写入，不同则根据差异制定应用页补写方案；完整一致后才启动。不要使用跨设备的 `--restore`、自动解锁或整片擦除来尝试恢复。
