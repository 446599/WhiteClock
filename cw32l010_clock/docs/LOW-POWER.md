# 低功耗移植说明

V1.1 引入低功耗优化：沿用原机深睡机制，以 RTC / GPIO 唤醒替代持续毫秒唤醒。实现已完成参考设备烧录、整片回读和运行观察；整机电流与续航尚未量测。

## 原厂流程

依据 `cw32l010_original_64k.bin`（SHA-256 `0f92f36672594320223d3a23815bd04f864b1163875ef61d41a2460bd0c80c71`）的 Thumb 反汇编：

| 地址 | 已确认行为 |
|---|---|
| `0x5730 → 0x31D6` | 主循环调用睡眠准备流程 |
| `0x5174` | 在 ADC 已开启的情况下关闭 ADC 并关闭相应时钟 |
| `0x4E04` | 清除 `SYSCTRL_CR1.LSIEN`（bit 3），关闭软件使能的 LSI，保留 LSE |
| `0x4EAC` | 清除 `SysTick.CTRL.TICKINT`，不再每毫秒中断 |
| `0x4B70` | 将 `SCB.SCR.SLEEPDEEP`（bit 2）置位，执行 `DSB / WFI` |
| `0x5734` | 主循环实际调用上述深睡入口 |
| `0x31F6 → 0x4E18` | 唤醒后恢复 LSI 工厂校准，开启 LSI 并等待其稳定 |
| `0x4738` | 重新开启 `SysTick.CTRL.TICKINT` |
| `0x10FA → 0x4538` | 设置 RTC 周期编号 3，即每分钟周期事件 |
| `0x110A..0x110E` | 使能 RTC 的 INTERVAL 中断（bit 6） |
| `0x42BC → 0x1228` | RTC 中断入口，检查并清除周期标志，登记后台事件 |

因此原厂采用的是“需要工作时运行，空闲时关闭高速活动，靠 RTC / GPIO 中断唤醒”，并非长期浅休眠。以上是具体调用路径的确认，不等于已穷举原固件所有页面的唤醒策略。

## 当前实现

- `power_idle()` 在 EPD、ADC、RTC 保存均空闲，设置无需落盘、画面已提交、按键无采样或待处理事件时进入深睡。
- 等待屏幕 BUSY、复位延时、采样和消抖时仍用浅休眠与毫秒 SysTick；SPI / 界面工作继续保持 24 MHz，不改变显示 LUT 和图像数据。
- 暂用 **每秒 RTC 周期中断**，不是原厂的每分钟周期。这样可保留番茄钟到时检测、温度调度和错误重试，不将原厂没有的交互计时机械改成分钟粒度。
- 深睡前停用 SysTick，关闭 SPI / ADC 外设时钟；保留 RTC、LSE 和 GPIO。醒后恢复寄存器与 SysTick，包括未完成的毫秒周期。
- 原厂另有运行期 LSI 依赖，睡前关闭、醒后重启；当前应用不使用 LSI，因此不机械复制其重启动作。高速 HSI 在 DeepSleep 中由硬件关闭，并按唤醒时钟配置恢复。
- 使用双读一致且非零的 `RTC_SSCNT`，结合秒字段计算实际睡眠时间。跨分钟取模，保留 1 / 32768 秒换算毫秒的小数余量；不按“每次醒来就加一秒”估算，因此按键提前唤醒不会让番茄钟走快。
- 保持 `WAKEUPCLK=0` 进入深睡，使硬件恢复原 HSI 分频；避免被强制切到 4 MHz 后仍按 24 MHz 设置 SPI / SysTick。唤醒后还原原寄存器值。
- 睡眠入口检查和时钟恢复期间屏蔽 ISR，不清除待处理按键 / RTC 中断。已使能的中断仍可唤醒 WFI，恢复后再运行处理程序。
- 关闭 PB2 / PB3 的 HCLK 硬件滤波，保留双边沿唤醒和 20 ms 软件消抖。HCLK 在深睡中关闭，不能靠其滤波器唤醒。
- RTC 时钟源、分频、周期配置或读数不满足条件时退回浅休眠；睡后时钟读取失败时停止继续深睡，保留诊断计数。

## 调试与恢复

**同时按住 SET 和 BACK 上电或复位**，本次运行禁用深睡，松手后仍保持，便于 SWD 连接和恢复。正常重启即可退出此模式。该模式不适合测量低功耗。

不关闭 SWD、不改 Flash 安全配置、不改变设置存储页。软件复位恢复和双键启动仍需硬件验证；不得将主机测试当作实机救援流程已通过。

构建清单可包含 `power_deep_entries`（深睡入口次数）、`power_sleep_ms`（已补偿睡眠毫秒）、`power_clock_failures`（睡后 RTC 读取失败次数）。这些不是电流测量。`main_loop_max_ms` 改为只统计活动处理时间，不把深睡等待计入阻塞。

## 验证与边界

主机测试覆盖：3600 次秒级深睡、时钟与 IRQ 状态恢复、按键提前唤醒、入口竞争、分钟回绕、小数累计、睡眠时钟故障退回，以及真实主循环运行 25 分钟专注计时、暂停 / 继续和五次完整提醒。原有画面散列、按键长按、主题和 EPD 回归仍需保持通过。

2026-11-19 的参考设备验证包含完整 64 KiB 回读、70 秒运行观察和显示 / 操作检查，记录见 [烧录校验](../../evidence/device_20261119_205153.json)与[运行观察](../../evidence/refresh_20261119_205336.json)。运行结束记录深睡入口 140 次、按键事件 42 次；EPD、RTC、按键溢出和睡眠计时错误均为零。这些计数不代表整机电流或全部 25 次任务完成均驱动了物理波形。

实测程序 SHA-256 为 `64e6870110e9e19e21f24577028f95f15d169ce2c65fe3a4888ff3b154992928`；发布程序与其等长，仅文件偏移 `17383` 的版本文字由 `0` 改为 `1`。发布版 SHA-256 为 `7ef17dbca32100496f88273069aa867a3c9125f0f55e0827342db403157ef959`，不冒用实测程序的整片哈希。

上机必须检查：冷启动、双键禁用深睡、RTC 周期唤醒、任意时刻按键唤醒、按住返回、设置保存、反色切换、番茄钟与 SPI 时钟。使用新 CR2032 并断开调试器，分别测待机电流、刷新峰值及电池端电压跌落，确认没有反复复位。

每分钟屏幕波形、周期全刷及电池脉冲负载仍消耗能量。连接调试器后的软件记录不等于断开调试器的待机电流；电流、整机续航、低温、长期稳定性与双键救援模式尚未全面验证，不提供月数或微安级整机功耗承诺。
