# AI 烧录交接文本

以下内容可直接提供给协助烧录的 AI。请补充电脑系统、仓库位置、烧录器型号和板卡照片。示例路径按仓库根目录描述，不依赖特定电脑的目录或烧录器 ID。

---

请协助我将 WhiteClock 正式固件烧录到兼容的墨水屏时钟。先阅读本仓库的 `README.md`、`cw32l010_clock/docs/FLASHING.md` 和 `cw32l010_clock/tools/device.py`，再根据实际电脑环境操作。不要修改功能、主题、LUT、电压或屏幕初始化参数。

## 设备信息

- 项目：https://github.com/446599/WhiteClock 。如果无法访问私有仓库，请要求我提供访问权限或文件，不要使用不明固件。
- MCU：CW32L010F8U6，Cortex-M0+，20 引脚；Flash 65,536 字节，RAM 4,096 字节。
- 屏幕：2.66 英寸黑白墨水屏，物理 152 × 296，横屏 UI 296 × 152。仅尺寸相同不能认定硬件兼容。
- 屏幕采用 UC8251 协议路径、原机五张 56 字节 LUT，具体面板料号没有完全确认。
- 按键：BACK=PB2（原 K1）、SET=PB3（原 K2），低有效。
- RTC：外部 32768 Hz LSE。
- 应用地址：`0x00000000` 起，长度必须不大于 64,000 字节，末端不超过 `0xFA00`。
- 设置页：`0xFA00`、`0xFC00`；安全页：`0xFE00`。禁止擦写这些区域。

## 接线约束

| 烧录器 | 时钟板 |
|---|---|
| SWDIO / DIO | PA7 |
| SWCLK / CLK | PA8 |
| GND | GND |
| VTref（如有） | 经确认的 MCU VDD，按烧录器说明连接 |

这不是 UART。PA7 / PA8 是 MCU 信号名，不是接插件脚序。仓库不包含所有批次通用的焊盘位置图；无法确认时先要求板卡正反面和主控 / 焊盘近照，必要时指导断电通断测量，不要猜测。

默认设备自身供电并与烧录器共地。先核对 VDD 和 SWD 电平，不能假定烧录器 VCC / 3V3 / VTref 是同一功能，不能并联两路供电或将 USB 5 V 接到 SWD。PA2 是屏幕 RST，不是 MCU nRESET。本流程使用软件复位，不要求接入 nRESET。

## 软件与目标文件

使用可被 pyOCD 识别的 SWD 烧录器；参考环境使用 WCH-Link，但不保证所有 WCH 型号和模式均兼容。用 `python -m pyocd list` 获取实际探针 ID，不能照搬脚本的默认 ID。

在 `cw32l010_clock/` 下建立 Python 环境并安装 `requirements-dev.txt`。芯片支持包在 `pack/WHXY.CW32L010_DFP.1.0.2.pack`，目标名称 `cw32l010f8`。

V1.0 发布目录为 `releases/whiteclock-v1-fast-20261020/`。目标 BIN 为 61,252 字节，SHA-256：

```text
4168abefc0c78b3616b113c409ae1da52b4ca56960b43bac1fb335b787d578a5
```

读取同目录 `manifest.json` 验证 BIN，必要时核对 HEX 与 BIN 一致。不用本地旧 `build/` 文件替代正式版本；烧录现成 BIN 不需要重编译。

## 操作顺序

1. 确认我的系统、仓库目录、探针 ID、供电、接线和目标版本。先检查文件哈希和芯片支持包，不连接硬件写入。
2. 仅只读连接，读取芯片签名、Flash / RAM 大小和保护状态；任一不符立即停止。禁止自动解除保护。
3. 读取本台设备全部 65,536 字节，保存原始 BIN 和 JSON 报告，计算并汇报哈希。保留独立副本；报告缺失或读取不完整时不能写入。
4. 向我汇报识别结果、目标镜像和本台备份位置，确认继续后，使用这次读取的整片哈希作为 `--expected-before-sha256`，按页烧录应用。
5. 再读取全部 65,536 字节，与目标应用、原页填充和保留尾部逐字节比较。只有 `VERIFY PASS` 和 `verified: true` 才表示写入成功；然后软件复位启动。
6. 引导检查首屏、SET 菜单、BACK 圆点移动、长按返回、七主题保存、番茄钟及五次全刷提醒。分别汇报文件校验、设备回读和功能检查，不把它们混为一项。

`tools/device.py` 默认只读。指定正式目录可使用下面入口，并按我的操作系统调整引号与环境激活方式：

```sh
python -c 'from pathlib import Path; import sys; sys.path.insert(0,"tools"); import device; device.BUILD=Path("releases/whiteclock-v1-fast-20261020").resolve(); device.main()' --probe <实际ID> --frequency 5000
```

确认后的写入使用同一入口，追加 `--flash --expected-before-sha256 <本次只读的完整64KiB哈希>`。该哈希不是发布 BIN 哈希，也不是其他设备或历史报告的整片哈希。

## 必须遵守

- 不整片擦除、不解除读保护、不写安全页、不覆盖设置页。
- `cw32l010_original_64k.bin` 是参考设备备份，仅用于当前工具的参考哈希检查与协议分析；不能当作我的原厂备份，也不能使用 `--restore` 将它覆盖到我的设备。
- 连接不稳时先修复供电和接触，可将 SWD 降到 1 kHz；不能循环擦写碰运气。
- 写入一旦开始但未校验通过，设备完整性未知。保存本次 `before_*.bin`、`program_pages_*.bin` 和报告，不反复复位、不宣称烧录完成。恢复连接后先整片比较，再决定是否补写应用页；不能用任意历史哈希放行。
- 不因屏幕相似就启用裁剪窗口、替换 LUT 或提高驱动电压。正式配置为快刷 LUT 开启、裁剪窗口关闭、全刷 / 快刷边框均 `0x47`。
- 如果没有本机操作能力，请给出逐步指导并等待实际输出，不虚构检测、备份、写入或校验结果。

开始时请先问我尚缺少的系统、探针和板卡信息；信息齐全后从只读检查开始。
