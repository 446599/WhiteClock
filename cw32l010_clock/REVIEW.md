# WhiteClock 验证说明

本文件描述验证方法和覆盖边界，不代表任意设备或重新编译的镜像已完成硬件验证。

## 自动检查

| 范围 | 检查内容 |
|---|---|
| 镜像 | 原始参考备份哈希、向量表、未解析符号、64,000 字节应用边界、至少 1 KiB 栈预算 |
| 日期与 RTC | 世纪日期、星期、BCD、LSE 保留、读写超时及时间 / 日期独立保存 |
| 设置 | 双页序号、CRC、最后提交标记、每个写入边界掉电恢复、相同值不重写 |
| 按键 | SET PB3 / BACK PB2、20 ms 消抖、同时按下、开机按住、长按边界、连发 |
| 菜单 | 六项循环、只读版本行、左侧圆点、正反色文字与提示边界 |
| 主题 | 七主题保存 / 取消 / 预览、141,120 组实时布局、14 帧固定散列 |
| 资源 | 固定独立参考的逐像素解码、所有字形列及描边、每帧解压工作量限制 |
| 刷新 | 3,528 组场景变更、跨度与整行等价、OLD / NEW 一致、冻结与重定向、周期全刷 |
| 调度 | 70 组单次 SET 进入菜单、20 组主循环场景、9 组番茄钟提醒场景 |
| 烧录保护 | 7 项模拟流程，包含实时哈希、保留尾部、回读失败和保护状态 |

C 测试开启 ASan / UBSan；GCC 对 `setjmp` / `longjmp` 的用例索引按 `volatile` 语义处理，避免优化后的值失效。Python 测试不访问硬件。

## 构建资源

发布主题位图随源码固定保存，独立参考位于 `tests/fixtures/theme-assets/`。普通构建和 CI 不重新栅格化主题字体，避免不同平台的字体组件造成非预期画面变化。修改资源需显式生成、审查候选图，再维护参考与散列；不能通过删除断言或自动更新参考使测试通过。

## 设备验证

每次写入都必须保留本机完整备份，以即时整片哈希保护写入，并核对全部 65,536 字节。应用页外区域必须与本次备份一致，完整通过后才允许启动。

功能检查应分别覆盖首屏、白底 / 反色、主题、菜单圆点、按键长按、时间日期保存、番茄钟完成和设置复位恢复。硬件样本记录保存在 `evidence/`；历史记录不替代新设备、新镜像的验证。

## 未覆盖范围

- 多批次板卡和面板兼容性。
- 低温、高温、长期残影与寿命。
- 完整功耗测量、走时精度及硬件栈水位。
- 精确按键到画面的延迟分布。
- 原生四灰波形；现有主题仅使用黑白空间抖动。
